你需要为游戏中的对话系统生成语料。玩家扮演食堂经理，与用餐者争锋相对。

## 背景设定

- **场景**：中国大学食堂，真实的日常运营场景
- **支付方式**：学生刷卡消费（不涉及现金找零）
- **服务限制**：不提供打包服务
- **对话性质**：用餐者投诉/抱怨 vs 经理回应

## 对话结构要求

### 用餐者发言（提问/投诉）

1. **内容特点**：
   - 描述具体问题现象（食物、卫生、服务、排队等）
   - 表达不满情绪（愤怒、失望、讥讽等）
   - 提出质问或要求
   - 可以理性陈述，也可以情绪化、无理取闹

2. **长度**：每段对话 2-3 句话，总长度 30-60 字为佳

3. **风格示例**：
   - 愤怒型："这[菜]里有[异物]，\我刚咬到一块硬的，牙都快崩了！\你们怎么做饭的？"
   - 讥讽型："你们这[汤]一点味道都没有，是[清水]吧？\我花钱买的是[菜]不是水！"
   - 强硬型："刚才队里有人[插队]，\你们[管理]在哪里？\每次来都有这种情况！"
   - 无奈型："这[配菜]都发黑了，\是不是放了太久，\还能吃吗？"

4. **换行规则**（重要！）：
   - 使用 `\` 在句子中间断行，控制显示效果
   - **不要只在标点符号后换行**，要在一小句内部换行
   - 目的：增强视觉节奏感，避免单行过长
   - 示例：
     - ✅ 好："这[菜]里有[异物]，\我刚咬到一块硬的"（在逗号后的小句中间断）
     - ❌ 差："这[菜]里有[异物]，\我刚咬到一块硬的，\牙都快崩了！"（只在标点后断）

5. **关键词标记 `[...]`**（核心功能）：
   - **用途**：标记玩家可以点击回应的词汇
   - **选择原则**：
     - 投诉的核心对象（菜、汤、米饭、服务员）
     - 问题的关键描述（异物、头发、冷、烫、慢）
     - 管理/制度相关（排队、管理、卫生、价格）
   - **密度控制**：每段对话 2-4 个关键词，间隔合理
   - **适合作为回答切入点**：
     - ✅ 好："这[菜]有[异物]"（可针对"菜"或"异物"回应）
     - ❌ 差："这[菜][有][异物]"（过密，没有意义）
   - **示例**：
     ```
     为什么今天[饭卡]扣了两次钱？\卡上明明只有一次消费，\我要解释清楚！
     → 可针对"饭卡"回应系统问题
     ```

### 经理回答（回应选项）

1. **`summary`（必填）**：
   - 显示在选项按钮上的简短文本
   - 长度：4-8 字
   - 概括回答的核心立场/行动
   - 示例：
     - "马上换一碗"
     - "确实是我们的问题"
     - "这不可能"
     - "我去核实一下"

2. **`text`（必填）**：
   - 完整的回答内容
   - 长度：15-40 字
   - 与 summary 对应，但更详细
   - **不应包含关键词标记 `[...]`**（只有用餐者发言才标记）
   - 同样可以使用 `\` 换行控制显示

3. **`kind`（必填）**：
   - `agreement`（赞同）：承认问题，道歉，承诺改进
     - 示例："确实是我们的疏忽，\我马上处理"
   - `objection`（反对）：否认问题，反驳投诉
     - 示例："我们每天都严格检查，\不可能有这种问题"
   - `perjury`（伪证/说谎）：推卸责任，编造借口
     - 示例："这是供应商的问题，\我们也没办法"
   - `question`（疑问）：反问，要求澄清，转移话题
     - 示例："您确定是在我们这里买的吗？\能描述一下具体情况吗？"

4. **回答多样性**：
   - 对于同一个投诉，生成 3-5 个不同 kind 的回答
   - 覆盖不同的应对策略（强硬、温和、敷衍、真诚等）
   - 示例：
     ```toml
     # 投诉：这[菜]里有[异物]

     # 回答 1: agreement
     [[item]]
     kind = "agreement"
     summary = "立即更换"
     text = '非常抱歉，\我马上为您\换一份新的。'

     # 回答 2: objection
     [[item]]
     kind = "objection"
     summary = "不可能"
     text = '我们有严格的\检查流程，\这不太可能发生。'

     # 回答 3: question
     [[item]]
     kind = "question"
     summary = "能看看吗"
     text = '能让我看看\具体是什么吗？\可能是食材本身的。'
     ```

### 表情和手势（Emoji）

1. **`emotion`（必填）**：
   - 表示说话人的**面部表情/情绪状态**，相当于立绘
   - 必须是 emoji 字符
   - 根据**文本内容的语义和情绪**选择，不是根据 kind
   - 用餐者常用：😠😡😤😞😢😭😰😨😱
   - 经理常用：😅😓😰😌😊🙂😐😕

2. **`gesture`（可选）**：
   - 表示说话人的**手势动作**
   - 必须是 emoji 字符
   - 选择具体的手势动作，不是抽象概念
   - 常用手势：👊🤚✋👋🤞🤏👈👉🤝👍👎👏🤙
   - **注意**：gesture 是说话人的动作，不是文本内容的图形化

3. **选择原则**：
   - ✅ 好：愤怒内容 → emotion="😠", gesture="👊"
   - ✅ 好：无奈内容 → emotion="😰", gesture="🤚"
   - ❌ 差：agreement 类型 → emotion="😊"（应该看文本内容，可能道歉时很为难 "😓"）

## 话题分类（可选但推荐）

为用餐者的投诉添加 `topic` 字段，便于系统根据游戏事件触发对应对话：

- `hygiene`：卫生问题（异物、头发、虫子、发霉、油渍、老鼠、蟑螂）
- `taste`：味道问题（没味道、太咸、太淡、怪味、焦味）
- `quality`：质量问题（冷、烫、不新鲜、剩菜、缺斤短两）
- `queue`：排队问题（插队、等太久、秩序混乱、服务慢）
- `hunger`：分量问题（太少、吃不饱、没肉）
- `tableware`：餐具问题（破损、脏、有裂痕）
- `appeal`：缺货问题（想吃的菜卖完了、选择少）

如果投诉不属于游戏内反馈系统，可以省略 topic（如饭卡、价格、服务态度等）。

示例：
```toml
[[item]]
text = '这[菜]里有[异物]，\我刚咬到一块硬的，牙都快崩了！'
emotion = "😠"
gesture = "👊"
topic = "hygiene"
```

## 生成格式（TOML）

### 完整示例：一个投诉及其回答

```toml
# === 用餐者投诉 ===
[[item]]
text = '这[菜]里有[异物]，\我刚咬到一块硬的，\牙都快崩了！\你们怎么做饭的？'
emotion = "😠"
gesture = "👊"
topic = "hygiene"  # 可选，推荐添加

# === 经理回答选项 1：赞同 ===
[[item]]
kind = "agreement"
summary = "立即更换"
text = '非常抱歉，\给您带来了不好的体验，\我马上为您换一份新的。'
emotion = "😓"
gesture = "🙏"
response_score = 0.8  # 可选：回答质量分数，-1.0 到 1.0

# === 经理回答选项 2：反对 ===
[[item]]
kind = "objection"
summary = "不可能"
text = '我们每天都有\严格的检查流程，\这种情况不太可能发生。'
emotion = "😐"
gesture = "🤚"
response_score = -0.5

# === 经理回答选项 3：疑问 ===
[[item]]
kind = "question"
summary = "能看看吗"
text = '能让我看看\具体是什么吗？\可能是食材本身的成分。'
emotion = "🤔"
gesture = "👈"
response_score = 0.2

# === 经理回答选项 4：伪证 ===
[[item]]
kind = "perjury"
summary = "供应商问题"
text = '这应该是供应商那边的问题，\我们也没办法，\只能换个供应商。'
emotion = "😅"
gesture = "🤷"
response_score = -0.3
```

### 字段说明总结

#### 用餐者投诉（Questions）
```toml
[[item]]
text = '...'        # 必填：投诉内容，使用 [关键词] 和 \ 换行
emotion = "�"      # 必填：表情 emoji
gesture = "�"      # 可选：手势 emoji
topic = "hygiene"  # 可选：话题分类（推荐）
```

#### 经理回答（Responses）
```toml
[[item]]
kind = "agreement"     # 必填：agreement/objection/perjury/question
summary = "立即更换"    # 必填：选项按钮文本（4-8字）
text = '...'           # 必填：完整回答（不含 [关键词]）
emotion = "😓"         # 必填：表情 emoji
gesture = "🙏"         # 可选：手势 emoji
response_score = 0.8  # 可选：-1.0~1.0，影响声誉变化
```

## 质量检查清单

生成内容前请确认：

- [ ] 用餐者投诉是否标记了 2-4 个合适的关键词 `[...]`
- [ ] 是否使用了 `\` 在句子**内部**换行，而不仅是标点后
- [ ] 每个投诉是否至少有 3 个不同 kind 的回答选项
- [ ] summary 是否简洁（4-8 字）且概括了 text 的核心
- [ ] emotion 和 gesture 是否符合文本的情感，而非 kind 类型
- [ ] text 内容是否真实反映中国大学食堂的场景
- [ ] 回答的 text 中是否**没有**包含关键词标记 `[...]`

## 常见错误示例

❌ **错误 1**：关键词过密
```toml
text = '这[菜][有][异物]'  # 太密集，没有意义
```
✅ 正确：
```toml
text = '这[菜]里有[异物]'
```

❌ **错误 2**：只在标点后换行
```toml
text = '这菜有异物，\我要投诉！\你们怎么做的？'
```
✅ 正确：
```toml
text = '这[菜]有[异物]，\我刚咬到一块硬的，\牙都快崩了！'
```

❌ **错误 3**：回答中包含关键词标记
```toml
[[item]]
kind = "agreement"
text = '我马上为您[换一份]'  # 回答不应有标记
```
✅ 正确：
```toml
[[item]]
kind = "agreement"
text = '我马上为您换一份'
```

❌ **错误 4**：根据 kind 选择 emotion
```toml
[[item]]
kind = "agreement"  # 因为是赞同，所以用笑脸
emotion = "�"
text = '非常抱歉，这是我们的失误'  # 但内容是道歉，应该用尴尬/为难的表情
```
✅ 正确：
```toml
[[item]]
kind = "agreement"
emotion = "�"  # 根据文本内容（道歉）选择
text = '非常抱歉，这是我们的失误'
```
