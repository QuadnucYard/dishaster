# Agent 设计

本文档描述游戏中各类智能体的基本要求和行为。所有行动和移动都需要时间执行。智能体之间存在碰撞避让，但仅保证逻辑上的距离不会太接近，不会发生物理碰撞。

具体数学模型见[建模](./modeling.md)。

## 用餐者（学生）

用餐者主要为学生，也包括老师等角色。他们具有大量隐参数，对玩家隐藏。这些参数影响其决策和行为。

### 基本属性

- **记忆**：影响后续决策。
- **菜肴喜好**：用向量表示偏好某些菜类，偏好不吃某些菜。菜肴选择连续性：有人喜欢连续吃相同菜，有人喜欢每天尝试新菜（用浮点参数控制）。如果全都是腻味的菜，则会离开食堂。
- **价格接受度**：根据预算区间点餐，若实际价格超出预期，会心情不好。
- **麻烦容忍度**：愿意去多个窗口买到想要的菜，但大多数偏好一站式服务。
- **餐桌选择**：优先找空桌，一伙人偏好一起坐。
- **耐心和等待上限**：影响排队行为。
- **食堂满意度**：初始值为居中值，随机上下浮动。根据用餐体验动态变化。若满意度降低到一定程度，每天有概率不来食堂（满意度越低概率越高）。这个概率也与性格相关。
- **饭量和饥饿程度**：影响点的菜量。

### 记忆

有短期和长期
- 短期：当次就餐。包括但不局限于：
  - 想要去的窗口
  - 看过的窗口
  - 拿过的餐具
  - 点过的菜
- 长期：持久于不同run中。可能会随时间衰退。包括但不局限于：
  - 吃过的菜
  - 对食堂的好感度

### 行为状态机

进场 → 观察窗口&思考 → 取盘 → 前往窗口 → 排队 → 点菜刷卡付费 → 寻找座位 → 就座 → 吃完反馈 → 离场。

- 观察思考逻辑由参数控制。该阶段 diner 的移动由决策决定。
  - 有一个数值控制欲望。会循环决策：
    - 观察窗口。观察的过程中会随机徘徊，接近尝试的窗口。
    - 判断窗口想不想吃
      - 观察和犹豫的过程中会偶尔冒出表情或简短符号反馈（思考气泡），用于展示当前想法。
      - 判断因素包括：自身喜好与菜品口味的匹配度，价格与自身接受度，排队长度
      - 如果之前没了解过这个窗口，会到窗口边上看窗口供应的餐再判断
    - 如果不想去这个窗口，重复上述逻辑。
    - 决定好吃什么后，会去该窗口排队
    - 如果没有想吃的，离开食堂。
  - 有的顾客已经想好了吃什么，不需要思考吃什么。但是可能会因为窗口队列过长而更改选择。
  - defer：如果他想吃的没有供应，会很失望
- 在窗口，排到队后：先点菜或汤，然后点饭。最后刷卡。
- 拿到饭菜后，以较慢速度四处寻找就近座位。优先选择完全空桌，如果没有空桌，则在所有空位中挑选 dirtiness 最低且距离最近的座位，并立即占位防止被抢。若在限定时间内仍找不到座位，则放弃就座并离场。
  - 目前吃完会恒定提高该桌的 dirtiness，后续可再细化为更丰富的随机变化。
- 取筷子放在取盘之后，吃饭之前（例如，带着筷子排队，消费后取筷子，将餐盘放到桌上后再取筷子）。不同人有不同习惯。
- （可选）去免费汤供应点打汤。同样存在排队。
- 坐下后会原地吃饭一段时间，期间计算满意度并有概率触发“食品安全事件”后反应（呕吐/投诉）。
- 将餐具交到最近的回收处
- 从最近的出口离开食堂。

### 排队

通过排队来取餐或餐具，或者送餐具。分成两种队：

- 有序：需要排成一列，禁止插队。窗口提供了队列参考位置，实际排队在旁边即可，大致形成一条队列（近似一条线）。需要在相应的寻路中找到队尾。
  - 虽然游戏中窗口朝向固定，但排队系统应当能处理任何队列朝向。不考虑队列拐弯
- 无序：没有队列，靠近目标地点即可，形成外围排了多层。（这个 case 可以考虑不抽象成队列）
  队列**没有**固定的位置，完全是自然形成的。当队首或队中某人离开时，后面走上来填充（按移动逻辑走过去，不是瞬移）

学生排队并估算等待时间。若超过耐心，会放弃或换窗口，并产生负面满意度。

#### 排队过程

- 如果排队目标尚无人排队，走到附近即可。
- 进入队之前时，需要经常检查有没有人已经排到了前面。
- 排队位置应当在横向相对前一个人有一定偏移，但不太远，这样更自然。
- 当前面的有人离开时（排队完成或中途退出），需要前进填补位置。
- defer：排队时，位置可能左右震荡

### 窗口选择

#### 关于菜

- 需要有特征向量，用于匹配菜品本身属性和个人喜好。具体表示形式待商议。
- 同一种菜可能在不同窗口有供应。如果制作不同，需要在特征向量上作区分，但是应当保证相似。
- 可以对特种作适当扰动产生变体。

#### 判定因子

- 菜肴品质（随机浮动，低质量不吸引人）。
- 价格（越高概率越低）。
- 队列长度（等待越长概率越低）。
- 个人偏好（偏好特色或节省）与随机因素。

#### 选择流程

- 长期记忆：对每个窗口和菜品有好感（以提供服务id为key）
- 来之前：预先有窗口和菜品的欲望。跟历史和喜好有关
  - 避开体验差的，倾向体验好的
  - 倾向符合口味的
  - 避开之前吃过的
- 来之后：通过观察，确定窗口的可用性和排队人数
  - defer：一次观察获取的信息有限，需要走到窗口附近
- 根据观察信息计算最终选择，然后到窗口排队


### 窗口服务

（不知道叫什么名比较好）
需要加入打饭菜的人员（起个合适的、正式点的名），作为 agent

流程如下：

- diner 将托盘放在窗台上（托盘是一个矩形，用于放餐盘和餐具）
- 打饭菜的人员打招呼
- 循环：
  - diner 指定要点的菜（气泡反馈，内容为菜的 emoji，dish 的 emoji 在 model 里指定）
  - 打饭菜的人员可能做出如下反应：
    - 听不清：反馈一个 ❓
    - 确认：走到他认为选的菜旁边，并反馈该菜的 emoji 加上 ❓
  - diner 根据反馈给出相应反馈
  - 确认无误后打菜，走到窗前放到 diner 的托盘上
    - 如果是称重计费的菜，在打菜后会将容器放到窗前的电子秤上（具体表现为，在走到窗前后，给出一个 ⚖+价格反馈，再将 dish 放到托盘上）
- 刷卡结算（给出价格反馈）
- diner 端着餐盘离开

注意：每步行动之间都有随机间隔

需要设计一个反馈系统（具体以气泡形式呈现，core 只管 emit event）。客户端在每个角色头顶展示最近一次反馈气泡，几秒后自动消失，不保留全局日志。

### 吃饭

- diner 取餐后，寻找空座位
  - 贴合现实：寻找的过程中走路速度比较慢，可能走走停停
  - 如果没有空座位就到处走（表情反馈一个不满）。
- 经过一段时间吃完
  - 后期细化：一遍吃饭一遍看手机
- 吃的过程中以及吃完后可能有反馈(暂时不做)。
- 将餐盘交到收残处（collector），然后从食堂入口离开
  - 端着餐盘（托盘）时走路慢

#### 满意度计算

满意度基于饥饿满足度、菜品味道（随机因子）、安全性（出现可疑物会重扣）、价格感受（消费压力）。
结果映射到表情：高满意 😁/🙂、中性 😐、不满 😡/😒、强烈不满/食品安全 🤮。仅供参考，具体表情由 client 决定

## 打饭菜的人（服务员）

服务员有固定工作位置，可在菜网格旁边一定范围内移动，到点菜足够近时才能打菜，把打的菜放到窗口的餐盘上。若是称重荤菜，多一个称重环节。

### 称重菜

- 荤菜按斤计价。
- 荤菜由若干块构成，每块重量符合正态分布或其他分布。具体重量动态生成。
- 服务员会按照客户需求量（按价格或重量）取适当的菜，但由于荤菜单块大小不一，实际会有随机浮动。

## 食堂工作人员（厨师）

厨师根据玩家指令完成任务后离场。厨师数量有限，只有闲置时才能出动。

- 厨师虽然看不见，但会在后台做菜。当天开始运营时默认所有菜都做好。若需补充菜，厨师需要消耗时间去做。做好后从屏幕最下后面出现，走到对应菜旁边加菜（动画表现为一堆 emoji 跳上去）。
- 补餐具的人员从角落门出现，走到餐盘架或筷子柜旁边，再原路返回。
